# Блок: engine-fix

## Назначение

Довести существующий движок до состояния, в котором на него можно опереться боту. Логику расчёта не трогаем — чиним то, что мешает вызывать движок из программы и то, что уже давало неверный отчёт на боевых проверках.

## API-контракт

Добавляются команды и поведение, остальные вызовы остаются как есть:

```
audit.py edit --n N [--qid CODE] [--level D1|D2|D3] [--zone ZONE] [--evidence "..."] [--comment "..."]
audit.py meta [--unit ...] [--partner ...] [--date ...] [--lang ...]   # правка шапки начатой проверки
audit.py init ... --partner "..."     # партнёр попадает в шапку отчёта
report.py pdf --out PATH              # ненулевой код возврата, если файл не создан
report.py letter                      # шаблон по наличию D2/D3
report.py html [--out PATH]           # тот же HTML, из которого собирается PDF
```

Имена флагов `edit` приведены к именам существующего `add` (`--qid`, `--evidence`), а `--code` и `--text` из первоначальной формулировки контракта приняты как синонимы: смешивать `--code` в правке с `--qid` в добавлении — ловушка для `domain`. `report.py html` добавлен сверх контракта: без него содержимое отчёта пришлось бы проверять разбором PDF, и он же нужен блоку `report` для сверки вида (T042).

Инварианты: повторный `add` с той же парой «код + зона» завершается ошибкой; номера записей сквозные и после `drop` не переиспользуются; `init` отклоняет пустую пиццерию и дату не в формате ISO.

## Зависимости

Нет. Строится первым и параллельно всему остальному.
