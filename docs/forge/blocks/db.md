# Блок: db

## Назначение

Дать проверкам место, где они живут после завершения: Postgres в Supabase плюс Storage под кадры. Идущая проверка остаётся в файле — база принимает уже завершённую (D027, D053).

## API-контракт

```python
push_inspection(chat_id: int) -> str          # id проверки в базе; повторный вызов не создаёт дубль
upload_photos(inspection_id: str) -> int      # сколько кадров выгружено в Storage
list_inspections(unit: str | None = None) -> list[InspectionRow]
```

Никто, кроме `domain`, не открывает `inspection.json`; никто, кроме `db`, не ходит в базу.

## Зависимости

`domain`.

## Definition of Done блока

- [ ] Схема заведена миграциями, а не руками: арендатор, точка, проверка, находка, кадр, версия чек-листа.
- [ ] В каждой проверке записана версия методики, по которой она посчитана — отчёт остаётся объяснимым после правки чек-листа (D033, D050).
- [ ] Формулировки хранятся строками `(entity_id, lang, text)`, сущности связаны кодами — добавление языка не требует миграции (D025).
- [ ] Заложена связь повторной проверки с исходной. Функция удвоения не строится: снята решением команды до следующего года (D029).
- [ ] Слив идёт на завершении проверки и повторяем: второй вызов не создаёт дубль.
- [ ] Падение базы не роняет проверку на точке: аудитор получает PDF, непролитая проверка видна и доливается позже.
- [ ] Кадры выгружаются в Storage за S3-совместимым интерфейсом; смена хранилища — правка конфига (D004, D054).
- [ ] Настоящие данные не трогаются проверками: смоук идёт на своей схеме и убирается за собой.
