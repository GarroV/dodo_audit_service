# Блок: infra

## Назначение

Поднять продукт одной командой там, где он должен жить, и сделать так, чтобы переезд не был переписыванием.

## API-контракт

```bash
docker compose up -d      # поднимает бота
make regress              # прогон движка на эталонных данных
make demo                 # демо-набор на английском
```

Переменные: `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `AUDIT_DATA_DIR`, `ALLOWED_TELEGRAM_IDS`, `STATE_DIR`, `BOT_MODE` (`polling` | `webhook`), `TZ`.

`bot`.

#### T100 — демо целиком на английском (**сам**)

Сам: работа исследовательская — надо было пройти демо целиком и решить
развилку про `STATE_DIR`; механического куска на полсотни строк тут нет.
Исполнителю ушёл только набор данных (см. ниже).

**Развилка, решённая мной: сид НЕ читает `STATE_DIR`.** У демо своя
переменная `DEMO_STATE_DIR`, по умолчанию `demo/state`. Почему не `STATE_DIR`:
это путь работающего стенда, и на сервере он указывает на настоящие проверки.
Читай сид его — `make demo`, запущенный на стенде, положил бы демо-проверку
рядом с боевыми, а демо-отчёт лёг бы в папку с отчётами партнёрам. Симметрия
с `AUDIT_DATA_DIR`, который сид перекрывает и обязан перекрывать: демо не
наследует пути стенда, у него своя пара. При этом переменная именно
переменная, а не константа: демо-стенд в `docker-compose.yml` ставит
`DEMO_STATE_DIR` и `STATE_DIR` в один путь своего тома — там они совпадают, и
это видно в файле.

**Про `--lang en`.** Отдельным аргументом сборщику он не передаётся и не
должен: язык отчёта уже записан в шапке проверки (`report_lang="en"`), движок
читает его оттуда (`lang = --lang или meta.lang`, `engine/report.py:624`).
Вторая запись того же факта — ровно тот дубль, который конституция запрещает.
Проверено фактически: имя собранного файла — `Audit Demo Pizzeria #1 - Demo
Auditor - 03.09.2026.pdf`, в содержимом отчёта кириллицы нет.

**Что нашёл русского, проходя демо целиком:**
- `ui_lang` и `speech_lang` демо-проверки были `ru` (умолчание
  `start_inspection`). Бот берёт язык интерфейса из состояния проверки —
  значит, на демо-пути он говорил бы по-русски. Мой файл, починено.
- письмо партнёру сид не собирал вовсе — проверять было нечего. Собирается,
  кладётся рядом с отчётом.
- **чужое, не чинил:** до начала проверки язык интерфейса берётся из
  `DEFAULT_UI_LANG = "ru"` (`src/bot/texts.py:28`), и приветствие демо-бота
  будет русским. Переменной для языка интерфейса нет — нужна правка блока
  `bot`, описано в отчёте диспетчеру.

#### T102 — демо не отстаёт от `main` (**сам**)

Сам: это выбор механизма и его обоснование, а не механическая работа.

**Развилка, решённая мной: профиль `demo` в том же `docker-compose.yml`,
плюс скрипт обновления на расписании площадки.** Что рассматривал и почему
отвергнуто:

- *Отдельный `docker-compose.demo.yml`* — второй файл расходится с первым
  молча, и это ровно та болезнь, которую задача лечит.
- *Реестр образов + watchtower* — требует публиковать образы наружу и
  поднимать ещё один сервис; наружу нам нельзя, а платить за реестр тем более.
- *GitHub Actions с деплоем по ssh* — нужен либо доступ извне на домашний
  сервер, либо self-hosted runner; и то, и другое за границами задачи.
- *Отдельный compose-проект для демо* — сильнее изолирует, но ломает главное
  требование «той же командой»: команда становится другой, и демо снова живёт
  своей жизнью.

Как устроено:

- `x-stand` — общая часть обоих стендов якорем, а не копией: сборка, образ,
  источник секретов. Демо физически не может собираться из другого образа.
- `demo-seed` (одноразовый) и `demo` (бот) под `profiles: ["demo"]`. Обычный
  `docker compose up -d` их не поднимает и демо-переменных не требует —
  проверено `docker compose config --services`.
- Изоляция: свой том `demo-state`, свой чек-лист `./demo/data:ro`, свой
  токен. Токен перекрывается на `${DEMO_TELEGRAM_BOT_TOKEN:-}` — пустое
  значение вместо наследования боевого из `env_file`. **Проверено запуском:**
  демо-бот без токена падает с внятным `BotConfigError`, а не молча
  перехватывает обновления настоящего бота.
- Доступы — из того же `.env` тем же механизмом (D059). Отличается только то,
  что обязано: токен, список ID, база. Всё это описано в `.env.example`, и на
  описание стоит проверка.
- `tools/demo_refresh.sh` — приводит копию к `origin/main` и пересобирает
  **поимённо** `demo-seed demo`: `up` без имён перезапустил бы боевого бота и
  оборвал идущие проверки. Вешается на расписание площадки (`schtasks` на
  Windows-сервере), сам туда не ходил — это T073.

**Что проверено фактически, а не по коду:**

- образ собрался; `docker compose --profile demo up demo-seed` внутри
  контейнера дал `Score: 92% grade B`, отчёт `Audit Demo Pizzeria #1 - Demo
  Auditor - 03.09.2026.pdf` и `letter.txt` на томе `demo-state`;
- письмо партнёру прочитано целиком из тома — английское, без единого
  русского слова;
- демо-бот без токена отказал громко;
- `demo_refresh.sh --check` отказал на грязном дереве с внятной причиной.
