# Блок: bot

## Назначение

Весь разговор с аудитором: начать проверку, принять материал, показать предложение, зафиксировать подтверждённое, дать поправить, завершить и отдать отчёт.

## API-контракт

Наружу — только Telegram. Внутрь — вызовы `domain`, `recognize`, `report`.

Состояния диалога: `idle` → `starting` (пиццерия, вид, язык) → `working` (приём материала) → `confirming` (ждём подтверждения записи) → `finishing`.

## Зависимости

`domain`, `recognize`, `report`.

## Definition of Done блока

- [ ] Отвечает только Telegram ID из списка разрешённых; чужому не отвечает ничего осмысленного.
- [ ] «Новая проверка» спрашивает пиццерию, вид и язык отчёта; дата — сегодняшняя.
- [ ] Незавершённая проверка не перезаписывается молча: показывается, чья она и от какого числа, с выбором «Продолжить» или «Начать новую».
- [ ] Комментарий связывается с фотографией тремя способами: подпись, сообщение следом, ответ на любое из ранее отправленных фото.
- [ ] Альбом склеивается по `media_group_id` с окном 1–2 секунды в одну запись с несколькими фотографиями.
- [ ] Фотография без комментария вызывает уточняющий вопрос и не фиксируется.
- [ ] Предложения показываются кнопками; запись появляется только после подтверждения.
- [ ] Подтверждение — одна строка: пункт, класс, зона, накопленный процент. Без таблиц после каждого кадра.
- [ ] Правки прямо в чате: удалить последнее, сменить зону, класс, переписать формулировку. Процент пересчитывается.
- [ ] Замеры пишутся записями `D0` (`INF09`, `INF10`, `INF11`) среди находок; блок `info` не используется.
- [ ] «Завершить» показывает итог и список зафиксированного, даёт поправить, затем отдаёт PDF файлом и письмо сообщением.
- [ ] Прерванная проверка продолжается после перезапуска бота — проверено фактическим перезапуском контейнера, а не по коду.
- [ ] Пачка сообщений, пришедшая с задержкой после потери связи, обрабатывается без путаницы в привязке комментариев.
