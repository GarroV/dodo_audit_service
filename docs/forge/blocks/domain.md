# Блок: domain

## Назначение

Единственная точка доступа к предметной области: чек-лист, зоны, состояние проверки, вызов движка. Ни один другой блок не открывает `inspection.json` и не запускает `audit.py`.

## API-контракт

Всё перечисленное импортируется из `src.domain`. Обязательные параметры — как в техплане; всё, что добавлено сверх него, необязательно и имеет значение по умолчанию.

```python
check_environment() -> Settings                               # проверка окружения на старте продукта
list_items(zone: str | None = None, kind: str | None = None) -> list[ChecklistItem]
list_zones() -> list[Zone]
get_item(code: str) -> ChecklistItem
allowed_levels(code: str) -> list[str]
checklist_version() -> str
get_state(chat_id: int) -> Inspection | None
start_inspection(chat_id: int, unit: str, kind: str, report_lang: str, *,
                 ui_lang: str = "ru", speech_lang: str = "ru", date: str | None = None,
                 city: str = "", partner: str = "", contact: str = "", auditor: str = "",
                 tenant: str = "default") -> Inspection
add_finding(chat_id: int, code: str, level: str, zone: str, text: str, *,
            comment: str = "") -> Finding
edit_finding(chat_id: int, n: int, **fields: str) -> Finding   # code, level, zone, text, comment
drop_finding(chat_id: int, n: int) -> None
attach_photo(chat_id: int, n: int, file_id: str) -> None
score(chat_id: int) -> Score
```

Типы (`src/domain/models.py`):

| Тип | Поля | Формулировки |
|---|---|---|
| `ChecklistItem` | `code`, `kind`, `levels`, `zones`, `days` | `process(lang)`, `question(lang)`, `applies_to(zone)` |
| `Zone` | `code`, `title_ru`, `title_en`, `share_pct` | `title(lang)` |
| `Finding` | `n`, `code`, `level`, `zone`, `text`, `comment`, `photos`, `zone_unusual` | — |
| `Inspection` | `chat_id`, `unit`, `kind`, `date`, `ui_lang`, `speech_lang`, `report_lang`, `checklist_version`, `tenant`, `city`, `partner`, `contact`, `auditor`, `findings` | `finding(n)` |
| `Score` | `pct`, `grade`, `counts`, `deductions`, `by_zone` | `label(lang)` |
| `ZoneScore` | `code`, `share`, `counts`, `loss`, `left`, `zeroed` | `name(lang)` |

**Язык — параметр, поэтому формулировки отдаются методом с языком, а не полем.** Неизвестный язык — отказ, а не молчаливый откат на русский: иначе партнёр получит отчёт, в котором часть текста внезапно не на его языке, и заметит это только он.

`Score` строится разбором вывода `audit.py score --json`. Собственного расчёта в блоке нет и быть не может — это проверяется контрактом `engine-not-imported` в `lint-imports`.

Данные читаются из каталога `AUDIT_DATA_DIR`. Переменная не задана или каталог неполный — падение на старте с внятным сообщением.

## Что нужно знать потребителям блока

- **Отказы.** `ConfigError` — окружение непригодно, продукт не должен подниматься. `ValidationError` — значение отвергнуто до вызова движка. `InspectionNotStarted` — в чате нет начатой проверки (бот предлагает начать). `EngineError` — отказ движка, `message` дословно от него.
- **Текст отказов движка написан для командной строки.** Дубль пары советует «`audit.py photo 1 --add ...`». Аудитору такое показывать нельзя — переформулировать при показе обязан бот (задачи T055, T056).
- **`counts` содержит и `D0`** — информационные записи (замеры, настройки печи, фото продукта). Они не влияют на процент, но в отчёте нужны. Перечня классов в коде блока нет: список приходит от движка.
- **`zone_unusual`** — зона не из списка пункта. Движок такую запись пропускает и лишь помечает; бот показывает пометку аудитору.
- **Служебные пункты (`kind` = `aggregate`, `info`) блок не прячет.** Отсеивать их — работа разбора (`docs/03-recording-rules.md`, правило 8).
- **`start_inspection` не защищает от перезаписи начатой проверки** — движок затирает состояние целиком и молча. Спросить «продолжить или начать заново» обязан бот (задача T052).
- **Формулировка, начинающаяся с дефиса, доезжает целой:** движку всё передаётся видом `--ключ=значение`.
- **Идентификатор кадра с запятой отклоняется**: движок режет список фотографий по запятой, и один кадр молча превратился бы в два несуществующих.

## Где что лежит

- **Состояние** — `STATE_DIR/chat_<chat_id>/inspection.json`, папка на чат (решение D007). Рядом движок оставляет `inspection.json.lock`.
- **Поля, которых у движка нет**, — в том же файле под ключом `domain`: `schema`, `chat_id`, `tenant`, `checklist_version`, `ui_lang`, `speech_lang`. Записываются под той же блокировкой, что берёт движок. Проверка должна быть одним объектом: при переезде на базу иначе теряется половина её сведений.
- **Язык отчёта — в шапке движка (`meta.lang`)**, потому что оттуда его берёт сборка отчёта. Второй копии у блока нет намеренно: две копии разошлись бы.
- **Версия методики** — `checklist_version.txt` в каталоге методики, если управляющая компания его завела («имя набора плюс дата»), иначе отпечаток самих данных: `local-<12 знаков sha256 от чек-листа, зон, критериев и ставок>`.
- **Движку передаются две переменные**: `INSPECTION_FILE` — путь к состоянию, `CHECKLIST_DIR` — каталог методики. Вторая обязательна: без неё движок берёт данные из своей копии рядом со скриптом или из форка `checklist_data/` в рабочей папке.

## Проверено фактически

- `make check` — формат, линт, `mypy --strict`, 156 тестов, покрытие 94 %, мёртвый код, границы модулей: всё зелёное.
- `make regress` — боевой якорь на месте: 97.5 % A (5×D1) и 97.0 % A (6×D1).
- Смоук на боевой методике из `.env` (временный `STATE_DIR`): старт проверки с тремя языками → три записи, включая `D0` → дубль отклонён → дозагрузка кадров → правка → удаление → оценка 99 % A и разбивка по зонам. В файле состояния пять ключей: `meta`, `findings`, `info`, `seq`, `domain`.
- Каждый новый тест прогнан на испорченной копии: подстановка проверялась на применение, откат — из копии, снятой до порчи. Порча ловила ровно свой тест. Два теста после этого усилены: «нет переменной — отказ» проходил и на реализации с тихим путём по умолчанию, а «правка вернула запись» — на реализации, собиравшей ответ из аргументов вызова вместо чтения состояния.

## Решения, принятые в блоке

| Решение | Почему |
|---|---|
| Поля блока — в `inspection.json` под ключом `domain`, а не в отдельном файле рядом | Проверка должна быть одним объектом: при переезде на базу или при переносе папки сведения не разъезжаются. Цена — повторение протокола блокировки движка (`flock` на `inspection.json.lock`); разойтись реализации не могут, блокировка опознаётся по имени файла |
| Язык отчёта не дублируется в блоке `domain` | Его читает сборка отчёта из шапки движка. Одна копия — один источник правды |
| Версия методики без новой переменной окружения | Явный `checklist_version.txt` в каталоге методики, иначе отпечаток содержимого. Переменных в `.env.example` не прибавилось, а отчёт годичной давности всё равно опознаёт свою версию |
| Мультиарендность — поле `tenant` в состоянии, но не в раскладке папок | Решение D005: форма данных сейчас, функции потом. Папки по арендаторам без функций мультиарендности были бы структурой ради структуры, а поле задним числом в готовые проверки не впишешь |
| Кеша методики нет | Каталог подкладывают томом снаружи; кеш означал бы работу по старой методике до перезапуска. Разбор 136 строк занимает доли миллисекунды |
| Проверка мёртвого кода сканирует `tests/` вместе с `src/` | Контракт блока сегодня зовут только тесты — `bot`, `recognize` и `report` появятся позже. Иначе проверку пришлось бы глушить списком исключений на весь контракт, и она перестала бы что-либо ловить. В таком виде она сразу нашла настоящий мёртвый код (`Finding.is_violation`), и он удалён |

## Что осталось соседним блокам

- **Тексты отказов движка не годятся для показа аудитору** (`audit.py photo 1 --add ...`). Переформулировать — блоку `bot`, задачи T055 и T056.
- **`audit.py init` затирает начатую проверку молча.** Защита — на боте, задача T052.
- **`--lang en` даёт смешанный отчёт** (текст находки, пиццерия и аудитор остаются как введены). Ограничение движка, здесь не лечится: состояние не хранит две языковые версии текста находки.
