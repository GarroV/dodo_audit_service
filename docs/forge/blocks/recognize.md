# Блок: recognize

## Назначение

Превратить комментарий аудитора (и, если нужно, кадр) в несколько предложений: какой пункт, какой класс, какая зона. Предложения, а не решения — фиксирует человек.

## API-контракт

```python
classify(note: str, photo: bytes | None, zone_hint: str | None) -> Suggestion
transcribe(audio: bytes) -> str
```

`Suggestion.candidates` — не более пяти вариантов `(code, level, zone, wording, confidence)`; `needs_human` поднимается, когда кандидатов нет или уверенность низкая. Пустой список — валидный ответ.

Вызов модели изолирован за одной функцией: смена провайдера или модели — правка конфига.

## Зависимости

`domain` — оттуда берётся перечень допустимых кодов и классов.

## Definition of Done блока

- [ ] Перечень сужается до кандидатов **до** вызова модели: по словам комментария и карте `data/photo-cues.md`. Все 136 кодов в запрос не уходят.
- [ ] Код возвращается строго из переданного перечня — гарантируется схемой ответа, а не проверкой постфактум.
- [ ] Класс возвращается только из разрешённых для этого пункта.
- [ ] Зона берётся из комментария или подсказки, а не выводится из вида кадра.
- [ ] Кадр анализируется только когда комментарий неоднозначен или расходится с изображением.
- [ ] Правила формулировок из `docs/03-recording-rules.md` зашиты в промпт целиком.
- [ ] Модель не пишет про масштаб за пределами кадра и не хвалит то, чего не проверяла, — проверено тестами на формулировках из разбора боевых ошибок.
- [ ] Голосовое перекодируется и транскрибируется; сбой транскрипции не роняет проверку, а просит написать текстом.
- [ ] Блок деградирует: при недоступной модели бот предлагает выбрать пункт кнопками вручную.
