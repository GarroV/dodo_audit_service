# Техплан: Dodo Audit Service

Как строим первую версию — телеграм-бота для выездных проверок. Что строим — в `docs/forge/spec.md`, принципы — в `docs/forge/constitution.md`, обоснования выбора — в `docs/forge/research-report.md`.

## Стек с обоснованием

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Python 3.12 | Задан существующим движком, переписывать его запрещено. Образ `python:3.12-slim` на Debian, не Alpine — из-за системных библиотек WeasyPrint |
| Телеграм | aiogram 3.31.0 | Встроенный конечный автомат ложится на пошаговый сценарий; роутеры делят диалоги на модули; хранилище сменяемо память → Redis без правки хендлеров |
| Альбомы | `aiogram-media-group` 0.5.1 (MIT) | Готовый декоратор с окном ожидания 1 сек — ровно задача «несколько кадров одного объекта = одно нарушение» |
| Разбор | OpenAI `gpt-5.6-sol`, модель — параметр конфига | Решения D010 и D013. Строгий выбор кода из перечня через JSON Schema с `enum` + strict, фото передаётся тем же запросом. Флагман взят потому, что разница с дешёвой моделью — 93 цента на проверку, а цена ошибки — неверный отчёт партнёру |
| Голос | OpenAI `gpt-4o-mini-transcribe` + `ffmpeg` в образе | Решение D008. Telegram отдаёт OGG/Opus, напрямую API его не принимает. $0.003 за минуту — около трёх центов на проверку |
| Отчёт | WeasyPrint 69.x | Решение D009. Чистый Python, без браузера, нумерация страниц через CSS Paged Media. В образ ставятся `libpango-1.0-0`, `libpangoft2-1.0-0`, `libharfbuzz-subset0` и шрифт с кириллицей |
| Состояние | `inspection.json`, папка на чат | Решение D007 (владельца). Обязательное следствие: атомарная запись и один слой доступа |
| Площадка | Docker Compose на домашнем сервере | Решение D003. Всё настраиваемое — через переменные окружения (D004) |

**Отброшено:** wkhtmltopdf (архивирован с января 2023, им собраны эталоны); headless Chrome и Playwright (образ 1.8 ГБ, лишняя точка отказа); Postgres в MVP (решение владельца D007); python-telegram-bot (модель `context.user_data` менее прямолинейна под строгий пошаговый сценарий).

## Архитектура

Слоями, снизу вверх. Нижний слой ничего не знает о верхнем — это проверяется машиной, а не договорённостью.

```
        bot          диалог: FSM, хендлеры, кнопки, доступ по Telegram ID
       ↙   ↘
recognize  report     разбор комментария и кадра  |  сборка PDF и письма
       ↘   ↙
       domain         чек-лист, зоны, состояние проверки, вызов движка
          ↓
      engine/*.py     существующий движок — вызывается подпроцессом, не импортируется
```

**Движок остаётся внешним.** `domain` вызывает `audit.py` и `report.py` как подпроцессы, передавая путь к состоянию через `INSPECTION_FILE`. Так расчёт оценки физически не может быть продублирован в коде бота — это техническая гарантия принципа, а не обещание.

**Данные предметной области лежат вне репозитория** (`data/` в `.gitignore`, решение D002). Путь задаётся переменной `AUDIT_DATA_DIR`; при её отсутствии продукт падает на старте с внятным сообщением, а не работает на пустом чек-листе.

## Блоки и граф зависимостей

| Блок | Назначение | Зависит от |
|---|---|---|
| `engine-fix` | Правки существующего движка: команда `edit`, честные коды возврата, сроки в PDF, два шаблона письма, `requirements.txt` | — |
| `domain` | Чек-лист и зоны из `data/`, состояние проверки с атомарной записью, вызов движка подпроцессом | `engine-fix` |
| `recognize` | Сужение 136 кодов до кандидатов, вызов модели со строгим перечнем, транскрипция голоса | `domain` |
| `report` | Сборка PDF через WeasyPrint, приведение вида к эталону, тексты писем | `domain`, `engine-fix` |
| `bot` | Диалог целиком: доступ, старт и продолжение, приём материала, подтверждение, правки, завершение | `domain`, `recognize`, `report` |
| `infra` | Образ, compose, `.env.example`, запуск на домашнем сервере, демо-набор на английском | `bot` |

## Контракты между блоками

**`domain` → всем.** Единственная точка доступа к состоянию и справочникам:

```python
list_items(zone: str | None = None) -> list[ChecklistItem]   # ChecklistItem: code, process, question, levels, zones, days
list_zones() -> list[Zone]                                    # Zone: code, title_ru, title_en, share_pct
allowed_levels(code: str) -> list[str]                        # какие классы допустимы для пункта
get_state(chat_id: int) -> Inspection | None                  # None, если проверки нет
start_inspection(chat_id: int, unit: str, kind: str, report_lang: str) -> Inspection
add_finding(chat_id: int, code: str, level: str, zone: str, text: str) -> Finding   # отказ, если пара «код+зона» уже есть
edit_finding(chat_id: int, n: int, **fields) -> Finding
drop_finding(chat_id: int, n: int) -> None
attach_photo(chat_id: int, n: int, file_id: str) -> None
score(chat_id: int) -> Score                                  # Score: pct, grade, label, by_zone, counts — ТОЛЬКО из audit.py
```

Никто, кроме `domain`, не открывает `inspection.json` и не запускает движок.

**`recognize` → `bot`.** Предложение, а не решение:

```python
classify(note: str, photo: bytes | None, zone_hint: str | None) -> Suggestion
# Suggestion: candidates[<=5] из (code, level, zone, wording, confidence), needs_human: bool
transcribe(audio: bytes) -> str
```

Пустой список кандидатов — валидный ответ: бот переспрашивает человека, а не выдумывает запись.

**`report` → `bot`.**

```python
build_pdf(chat_id: int) -> Path        # исключение, если файл не создан — не код успеха
build_letter(chat_id: int) -> str      # шаблон выбирается по наличию D2/D3
```

**`bot` → наружу.** Только Telegram. Никаких HTTP-эндпоинтов в первой версии.

## Проверки качества

Ставятся до первой строки кода продукта, когда нарушений ноль.

| Роль | Команда | Инструмент |
|---|---|---|
| Формат | `ruff format --check .` | Ruff |
| Линт | `ruff check .` | Ruff, наборы `E`, `F`, `I`, `B`, `S`, `ASYNC`, `RUF` явным списком в `pyproject.toml` |
| Типы | `mypy --strict src/` | mypy. Строгий режим с первой строки; `engine/` исключён — он существующий и не наш |
| Тесты и покрытие | `pytest --cov=src --cov-fail-under=N --junitxml=reports/junit.xml` | pytest, pytest-cov. Порог **относительный**: не ниже прошлой приёмки, ставится по факту с округлением вниз |
| Мёртвый код | `vulture src/ .vulture-ignore` и `deptry .` | vulture — код, deptry — зависимости. Файл исключений ведётся с причиной на каждую строку: у aiogram хендлеры выглядят неиспользуемыми |
| Границы модулей | `lint-imports` | import-linter, контракты в `pyproject.toml` |

**Машинный отчёт прогона:** `reports/junit.xml` (JUnit XML). Приёмка блока сверяет по нему состав прогона — сколько проверок выполнено и сколько пропущено. Код возврата одинаков и при двухстах проверках, и при нуле зарегистрированных, поэтому отчёт пишется самой командой тестов, а не добавляется позже.

**Границы из графа блоков**, дословный перенос:

```ini
[importlinter]
root_packages =
    src

[importlinter:contract:layers]
name = Блоки идут слоями, обратный импорт запрещён
type = layers
layers =
    src.bot
    src.recognize : src.report
    src.domain

[importlinter:contract:engine-not-imported]
name = Движок вызывается подпроцессом, а не импортируется
type = forbidden
source_modules =
    src.bot
    src.recognize
    src.report
forbidden_modules =
    engine
```

Второй контракт — техническая гарантия принципа «оценку не считать заново»: импорт движка мимо `domain` роняет прогон.

**Регрессионный прогон** — отдельная команда, обязательная после любой правки движка или данных:

```bash
make regress   # belgrade-1 → 97.5 %, A, 5×D1 ; belgrade-2 → 97.0 %, A, 6×D1
```

**Карантин свежих версий:** pip не умеет `min-release-age`, аналога ключу npm нет. Вместо него — версии в `requirements.txt` прибиты точно (`==`), обновление версии проходит отдельным изменением, а не подтягивается само.

**Что НЕ включаем и почему:** мутационный прогон (дороже в разы, критичный модуль — движок, а он и так под регрессом на боевых данных); диф контракта API (раскатка одна, HTTP-поверхности нет); бюджеты страницы и проверка доступности (нет экранов); порог дублирования (воюет с правилом «абстракция после устоявшегося повтора»).

## Риски

| Риск | Чем грозит | Что делаем |
|---|---|---|
| **Качество разбора комментария** | Слепой прогон дал 1 верную фиксацию из 10. Плохие предложения замедлят аудитора сильнее, чем ручной ввод | Кандидаты кнопками, а не единственный вариант; пустой список — переспросить; сужение перечня по `photo-cues.md` до вызова модели |
| **Вид отчёта поедет** относительно эталона | Партнёр получит документ, не похожий на прежние | Сверка глазами на боевых данных до сдачи блока, правка CSS до совпадения |
| **Связи нет в морозильной камере и подвале** | Сообщения уходят с задержкой пачкой, порядок ломается | Полагаемся на очередь самого Telegram, своей не строим. Бот обязан корректно принять пачку, пришедшую позже, и не перепутать привязку комментариев к фото |
| **Битый JSON на альбомах** | Потерянная запись или неработающая проверка на середине обхода | Атомарная запись: временный файл, `os.replace`, блокировка на чат. Тест на параллельную запись обязателен |
| **Срок четыре дня** | Успеваем не всё | Порядок блоков такой, что после `engine-fix`, `domain`, `bot` и `report` проверку уже можно пройти. `recognize` деградирует до ручного выбора пункта кнопками, если модель не готова |
| **Форк чек-листа** | `manage.py` создаёт `checklist_data/` в рабочем каталоге, и разные чаты начинают считать по разной методике | Правки чек-листа в MVP запрещены; `AUDIT_DATA_DIR` задаётся явно, наличие форка проверяется на старте |
| **Ключ и токен ещё не получены** | Стройка упрётся | `Q001` открыт, `Q002` отвечен. Блоки `domain`, `engine-fix`, `report` строятся без них |
