# Конституция проекта

**Dodo Audit Service** — сервис выездных проверок пиццерий.
Согласована с владельцем 2026-08-28. Статус: ждёт утверждения на гейте перед стройкой.

## Принципы качества

1. **Правильность отчёта важнее скорости работы бота.** Отчёт уходит партнёру и становится основанием для требований к нему. Лишняя секунда ожидания не стоит ничего; неверная буква оценки стоит доверия к системе. Один отчёт уже ушёл партнёру с буквой, поставленной моделью «на глаз» вместо расчёта.

2. **Оценка считается движком, и только им.** Проценты, буква, разбивка по зонам, сроки устранения — исключительно через `engine/audit.py score`. Ставки вычетов и пороги букв живут в `data/scoring.json`; дублировать их в коде запрещено. Любая реализация расчёта где-то ещё — дефект, независимо от того, совпал результат или нет.

3. **Модель предлагает, фиксирует человек.** Запись по **кадру** не попадает в отчёт без подтверждения аудитора. Слепой прогон по боевым фотографиям дал одну верную фиксацию из десяти — это измерение, а не осторожность.

   **Уточнение от 03.09.2026 (решение D064, владелец).** При фиксации **словами** подтверждение снято: аудитор сам назвал и зону, и суть, угадывать нечего. Принцип держится там, где система угадывает, — то есть на кадрах. Оговорка, высказанная владельцу до решения и оставшаяся в силе: сопоставление слов с номером пункта тоже промахивается — на боевом примере «кассовая зона, просрочка чизкейк» слова поднимают единственный код `CLN02`, а верный `PRD10`, — поэтому промах становится тихим, и показ записи обязан быть заметным. Владелец сказал «потом добавим»: это возврат к вопросу, если тихие промахи пойдут, а не отмена принципа.

4. **Не утверждать больше, чем видно.** Система не пишет про масштаб за пределами кадра, не додумывает характер повреждения и не хвалит то, чего не проверяла. Положительная оценка требует такого же основания, как отрицательная. Правила целиком — `docs/03-recording-rules.md`, они зашиваются в промпт, а не в комментарии к коду.

5. **Сущности связываются кодами, никогда формулировками.** Формулировки переводятся и правятся, коды — нет.

6. **Форма данных — сейчас, функции — потом.** Всё, что дорого переделывать задним числом, закладывается в первой версии, даже если работать начнёт позже: мультиарендность, версии чек-листов, переводы строками `(entity_id, lang, text)`, три раздельных языковых поля (интерфейс, речь аудитора, отчёт). Функции при этом не строятся раньше срока.

7. **Площадка — деталь реализации.** Продукт поднимается через `docker compose`, всё настраиваемое живёт в переменных окружения, база доступна по `DATABASE_URL`, фотографии — через S3-совместимый интерфейс, режим бота переключается переменной. Переезд с домашнего сервера должен стоить перенос дампа и смену DNS, а не переписывание.

## Тестовый стандарт

**TDD для новой функциональности:** красный → зелёный → рефактор.

**Регрессионный якорь, который нельзя ломать.** На данных из `examples/` движок обязан выдавать ровно:

```
belgrade-1 → 97.5 %, оценка A, D1=5, D2=0, D3=0
belgrade-2 → 97.0 %, оценка A, D1=6, D2=0, D3=0
```

Любое расхождение — регрессия, блокирующая приёмку блока. Прогон обязателен после каждого изменения движка или данных.

**Обязательные типы тестов:**
- unit — разбор комментария, выбор кода, определение зоны, склейка альбома, форматирование подтверждения;
- integration — путь «сообщение в чат → запись в состоянии → пересчёт оценки»;
- сквозной смоук — полная проверка от старта до PDF на подготовленном наборе сообщений.

**Критичный путь, который не сдаётся без теста:** фиксация записи, правка записи, расчёт оценки, сборка PDF, продолжение прерванной проверки.

**Покрытие** — не ниже, чем на прошлой приёмке. Ориентир 80 %, но сам по себе процент блок не заворачивает.

**Правило дороже покрытия: проверка, которая не падает на испорченном входе, — не проверка.** Каждый новый тест прогнать на намеренно испорченной копии и убедиться, что он падает и печатает внятную причину. Саму порчу тоже подтвердить: если подстановка не применилась, негативный прогон окажется фиктивно зелёным.

**Отдельный запрет, выросший из находки 28.08.2026:** ни одна операция не имеет права возвращать код успеха, не сделав работу. `report.py pdf` возвращал `exit=0`, не собрав файл. Любой вызов, у которого есть наблюдаемый результат (файл, запись, отправленное сообщение), проверяет этот результат, а не только отсутствие исключения.

## Docs-as-DoD

Изменение не закрыто, пока документация, описывающая изменённое поведение, не приведена в соответствие — **в том же изменении**.

Обязательно обновляются вместе с кодом:
- `docs/04-engine.md` — при любой правке движка: команды, дефекты, неочевидное поведение;
- `docs/06-mvp-bot.md` — при изменении сценария бота;
- `.env.example` — при появлении новой переменной окружения;
- `CHANGELOG.md` — на каждое принятое изменение;
- `docs/forge/blocks/<блок>.md` — статус и фактический контракт блока;
- `README.md` — если изменился порядок запуска или проверки.

Инвентари (команды движка, переменные окружения, коды пунктов) сверяются **с исходником**, а не по памяти. Один факт живёт в одном месте, остальные ссылаются.

## Правила безопасности

- **Секреты не попадают в git никогда.** Значения — только в `.env` (в `.gitignore` с первого коммита), в документации и анкете — только имена переменных. Закоммиченный `.env.example` с именами и безопасными значениями обязателен: без него проект не поднять заново.
- **Репозиторий публичный.** Это меняет цену ошибки: всё, что коммитится, читается посторонними. Методика управляющей компании (`data/`) и боевые проверки с фотографиями и отчётами (`examples/`) в индекс не попадают. Перед каждым коммитом, добавляющим файлы, проверяется, не уехало ли туда чувствительное.
- **Персональные и коммерчески чувствительные данные:** ФИО аудитора, названия точек партнёров, их оценки и фотографии рабочих зон. В логах — идентификаторы, не содержимое. В сообщениях об ошибках наружу — без данных проверки.
- **Доступ к боту** — по списку разрешённых Telegram ID. Незнакомый отправитель не начинает проверку и не получает отчёт.
- **Валидация на границах:** всё, что приходит из Telegram и от модели, проверяется до записи в состояние. Код пункта принимается только из перечня допустимых, класс — только из разрешённых для этого пункта, зона — только из справочника.

## Демо-режим

Демонстрационный режим строится на **изолированном наборе данных**, никогда на боевых проверках: собственный демо-чек-лист, вымышленная точка, синтетические фотографии.

**Язык демо — всегда английский**, независимо от того, что интерфейс продукта русский.

Демо-набор идемпотентен: повторный запуск сида возвращает демо к чистому наполненному виду, а не накапливает мусор. В первой версии демо — это команда, поднимающая бота с демо-данными; когда появится веб, к нему добавится точка входа без регистрации.
